# Trace Web v1 现有原型整合：首批并行契约

## 用户已确认的方向
已有五组页面与资源不重做；固定视觉资产和公共组件，先完成真实可用的 Web，桌面封装后置。用户特别要求一个独立模型摸清“功能接续有感”，避免页面跳转与状态变化莫名其妙。

## 当前现场
app 位于 trace-runtime/apps/desktop，原生 JS/CSS，无需因名称或整合而迁移框架。首页与 matters 已在一份内存 model 上连通；刷新重置。chain/worksite/compare 是 artifacts 内独立可执行模块，尚未接入 app。左下头像只是关于原型；首页全部进 matters，matters 全部痕迹仍回 overview。搜索只是当前会话数据。

## 不变边界
1. root 唯一 app / 公共任务记录 writer；三个 worker 只写各自独占目录。不要改原 artifacts、原图、app、插件、锁文件、全局 Skill 或用户数据。
2. 不新生图、不新下载组件、不换视觉方向、不移动/删除旧资产、不全局装字体。必要差异先标为候选，不靠最新文件时间认定最终版本。
3. 同一事情、来源、理解、工作必须保留 ID 与版本关系；挑战不等于采用，候选不等于用户认可，送达不等于应用，删除关联不删原始材料。
4. 无来源/无网络能力不得生成假外文或冒充真实模型响应。账号、云同步、外部授权与发送能力均未确认；首批不增加假入口或外部副作用。
5. 本批的目标是给出可落地的接续契约、可验证的资产锁定候选、跨模块 host 适配及测试。不是声称全部 Web 已接好。实际持久化与路由接入由 root 核验现有 runtime 后实施；不能靠保存整个原型 state JSON 绕过对象/示例/草稿边界。
6. 已有 4173 服务由前轮 root 持有，不启动重复服务、不杀用户进程、不操作用户现有浏览器标签。需要运行时用自己的隔离 fixture/context，并关闭自己创建的进程。

## 输出边界
- experience/: 接续断点实证、入口/返回/变更可见性表、具体文案与可执行验收场景。产品未定案与代码缺陷分开。
- assets/: approved-assets.candidate.json、资产/组件选择与重复清单、只读 hash/引用核验脚本和结果。候选不等于全部已发布。
- state/: 既有 reducer/selector 跨模块契约差异、纯 host/adapter 候选及独立 Node 测试、真实存储边界建议。不直接改业务 runtime。
- coordination/: root 的基线/派发/接口裁决/整合次序。

## 交叉协作
experience 先发最重要 5 个断点给 root 和 state；assets 先发两套原字体/共享鸟图/场景背景的正式候选给 root；state 先发一个 matter ID 从概览→一件事→对照→返回仍保持身份的接口给 root 和 experience。发现冲突先提报，不让三个 worker 各设计一套导航或数据。

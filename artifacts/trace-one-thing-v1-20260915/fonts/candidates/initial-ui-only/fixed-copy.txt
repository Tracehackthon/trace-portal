为什么收藏之后，很少再回来？
约四分钟阅读
这是用于原型的示例文章，不是当前浏览器内容。
我们每个人都会收藏一些内容。也许是一篇文章、一个网页，或者一段话。当时觉得很重要，担心以后找不到，就先保存下来。
但一段时间后再回头看，收藏夹里已经堆满了各种内容。真正能想起来为什么收藏的，却寥寥无几。
这并不是因为我们不够自律，而是人的记忆在当下和未来之间，本就存在落差。保存一段内容，不一定保存了当时为什么在意。重新读到时，我们可能认得这些文字，却想不起自己的问题。
也许我们需要的，不只是一个收藏的动作，而是在收藏的同时，留下一点当时的想法，哪怕只是一句话。

# Trace｜一件事的连续 UI 页面 v1

> 一件事持续存在，界面随当前动作展开。这里是一组静态交互概念，不是 11 个互不相关的功能模块。

## 本套内容

2026-09-15，使用内置 `image_gen` 工具生成。围绕同一示例「收藏后为什么接不回来」，先生成 10 张关键状态，再补第 11 张修订真正落回后的状态。全部为 1672 × 941 PNG。

可以按 01—11 顺序看故事，但真实用户不必依次完成，可以在任意处停下、直接写或先去尝试。第 02 张演示已有停点的恢复态，不是要求第一次输入就必须拥有一段历史。

## 页面与动作

| --- | --- | --- | --- | --- |
| [01](01-阅读现场-留下一点.png) | 阅读现场 | 交进选中片段与一句话 | 留一下；或展开聊聊 | 来源与原话保留，未形成结论 |
| [02](02-气泡展开-接着这里.png) | 气泡展开 | 从已有气泡回到这件事 | 围绕停点继续，或先自己写 | 恢复问题，而非默认重读全部聊天 |

## 怎样串起来看

- **最短思考闭环：**01 留一点 → 02 找回停点 → 03 围绕一处 → 05 自己写 → 06 收起 → 07 再拿起。
- **需要外部依据时：**从 03 或 05 打开 04，接回当前具体位置后回到原工作面，不另开一套内容仓库。
- **进入实践时：**05 或 07 → 08 带去本次工作 → 09 在原生 Agent 旁边承接 → 10 比较结果 → 11 修订落回。
- **只留下结果：**10 的「只留结果」不进入理解修订；原来的理解不自动改变。
- **看看来路：**仍然是按需的追溯入口，不用完整轨迹图代替默认操作界面；本组没有重新绘制全历史视图。

## 本套保留的设计判断

- Trace 的名字、水墨支流、轻玻璃面、深松绿、少量琥珀色和单只飞鸟延续既有视觉方向。
- 不设置固定侧边栏；同一件事的身份由顶部位置与内容关系保持。
- 来源、建议解释、自己的草稿、一次工作尝试、真实经历之间保持区分。
- 原生 Agent 是工作主场，Trace 不复制另一个工作聊天。
- 第 11 张明确展示修订后状态：不是停在确认按钮，也不只新增一份孤立总结。

## 已完成的检查与修正

- 逐张查看生成结果；对 01、04、08、10 做了一次针对性修正：外部阅读场景、重复飞鸟、带去工作时的最新背景、修订前后的内容连续性。
- 最终 11 张均已复制到本目录；尺寸与 SHA-256 来源一致性验证见 [图片校验](图片校验.json)。源生成图未删除，旧的六张功能概念图与首页图未覆盖。
- 提示词、初始来源、修正提示词与最终选用来源见 [生图提示词与来源](生图提示词与来源.json)。工具没有暴露精确模型版本号，未自行推定。

## 仍然是概念，而非已验证交互

- 图片中的文章、引用、观察、工作与使用结果均为示例，不是已经发生的真实用户研究或实际接入记录。第 09 张的原生 Agent 界面为示意，不是当前 Codex 的运行截图。
- 尚未实现点击、动态布局、键盘操作、焦点恢复、真实保存与撤销、原生宿主接入或跨端同步。没有把图片和哈希验证当成业务验收。
- 生图中的小字、字形、局部建议与原句逐字对应、组件尺寸和操作文案仍需在原型实现时校准；静态图不替代正式功能定义。
- 分支迁移、错误关联修复、长内容、空状态、资料失效与失败重试仍需继续做交互状态设计，本套未分别生成它们的完整页面。

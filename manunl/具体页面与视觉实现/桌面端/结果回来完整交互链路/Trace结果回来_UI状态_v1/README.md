# Trace 结果回来：五种核心 UI 状态 v1

生成日期：2026-09-15。

本组承接本轮「结果回来：比较与修正」完整 UI 交互链路讨论，是桌面端静态视觉参考，不是可点击原型，不代表结果保存、版本更新、宿主接入或真实使用效果已经实现与验证。没有覆盖此前的核心功能概念图。

## 同一个案例

在 Codex · harness 中尝试气泡原位展开。用户带回一次原型试用感受：

> 我试了原型。原位展开让我认出是哪件事，但我还是不知道接下来该想什么。

它准备接回「收藏后为什么接不回来」，先比较观察、解释与未确认部分，再由用户决定是否给当前理解补上一个边界。

图片中的试用、来源附件、原理解与修订结果均为假设交互内容，不是项目测试记录或真实用户验证证据。

## 看图顺序

| 图片 | 当前焦点 | 关键动作与边界 |
| --- | --- | --- |
| 01-结果带入态.png | 带入实际观察，核对准备接回的位置 | 添加或移除材料、换一处、先不关联、先留结果、展开比较；理解未修改 |
| 02-比较展开态.png | 当时准备试什么，这次发生了什么 | 分开实际观察、个人解释和未确认部分；补充、纠正或先留到这里 |
| 03-影响辨认态.png | 结果影响的是哪一句、哪一部分 | 选中“接续思考”，建议补上边界；“限制”为待确认建议，不是已经采用 |
| 04-修订确认态.png | 精确查看修改前后、依据与作用范围 | 可编辑、暂存草稿、暂不修改；只有确认后保存成功，才能进入更新完成态 |
| 05-回接完成态.png | 实际结果与用户确认的理解变化回到同一件事 | 查看旧版本、回到这件事、再带去试一次、撤销修改；仍保留未决问题 |

这五张是同一件事逐渐展开的五种状态，不是五个独立导航页，也不是必须走完的五步向导。

## 贯穿的交互边界

- 保存结果不等于认可解释，认可解释不等于修改理解。
- “先留结果”“只留结果，暂不改理解”都是正常结束方式，不能自动跳成第五张的已修订状态。
- 实现成功不能证明真实使用有效；一次个人试用不泛化为所有用户的事实。
- 同次实践可以对不同判断产生不同关系，不必给整件事评成支持或推翻。
- 修订默认只影响这件事的当前理解，不自动修改项目规则、发布能力或重做进行中的工作。
- 撤销理解修改仍保留原始实践结果。
- 第五张假设用户明确确认且保存成功；失败、处理中或草稿不能显示同样的成功回执。

## 视觉一致性

- 沿用 Trace 图标、无固定侧栏、左下角个人入口、象牙白与青绿色、水墨山水、细支流与气泡。
- 每张一只小飞鸟表达当前注意力。
- 琥珀色表达待比较、待确认与草稿；绿色确认状态不提前出现在理解修订上。
- 图片作为信息层级与构图参考。落地时仍需验证字号、文字对比度、背景干扰、键盘操作与减少动态效果；静态稿不证明可用性。

## 未单独画出的分支

“只保存结果、不修改理解”的完成回执、关联错误修复、未关联结果、版本冲突、重复结果、保存失败与重试、暂停恢复、再次带去工作的目标选择等边界，仍需在可交互原型中展开。本组只覆盖本轮选定的五种关键画面，不宣称覆盖全部交互分支。

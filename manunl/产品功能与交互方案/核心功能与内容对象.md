# Trace 核心功能与内容对象

> Trace 围绕一件仍在变化的事，让用户能够留下一点、从真实停点继续、形成自己的理解、带去使用，并让后来的结果回来改变它。

## 这一份属于哪一层

本文属于产品的**核心功能架构层**，位于[产品交互链路](../产品交互链路/思考与学习阶段/README.md)之后、[产品界面与交互设计](../产品界面与交互设计/README.md)之前。

它正式回答三件事：

1. Trace 围绕什么核心对象工作；
2. 用户可以使用哪些核心功能；
3. 每项功能会留下什么以后还能继续使用的内容。

[功能与交互骨架](功能与交互骨架.md)保留从用户处境到交互位置的整体推导，[功能候选与使用方式](功能候选与使用方式.md)保留 1—11 项详细行为与边界。本文在两者之上收束当前采用的功能名字与内容对象，不重复展开所有场景。

这里确定的是产品功能语言，不等于已经确定页面菜单、按钮文案或技术模块，也不表示功能已经实现和验证。后续页面可以调整呈现方式，但不应因为某种 UI 看起来新奇，就改变这些功能要解决的问题。

## 命名判断

Trace 不从“知识库、知识图谱、AI 对话、任务管理”等通用模块开始命名。它的功能名来自用户在完整链路中真正要做的动作：

- 此刻先留下一点；
- 后来从这里接着；
- 需要时找一个真实对照；
- 把逐渐分清的部分写成自己的理解；
- 让它进入实际使用；
- 再让真实结果回来。

当前采用六个核心功能名：

1. **留下一点**
2. **从这里接着**
3. **找个对照**
4. **我的理解**
5. **带去用**
6. **结果回来**

这些名称保留用户原本的语言，先说明能做什么，不用抽象名词要求用户理解产品方法论。具体场景里的动作可以更明确，例如“留一下”“换个情形”“接到这里”“带去当前工作”“带回结果”。

## Trace 围绕什么工作

### 核心对象：一件事

“一件事”是当前用于设计的内部简称，指一件用户仍然在意、仍可能继续变化的事情。完整表达是：

> **一件仍在变化的事。**

它可能从一段知乎原文、一个模糊感受、一次讨论、用户自己写的一句话或工作中的实践发现开始。它不要求一开始就有明确目标、标题和分类，也不要求最终形成结论。

例如：

> 收藏后为什么接不回来？

围绕它，后来可以出现新的原文、讨论、自己的理解、反例、工作尝试和实际结果。它们不是几份互不相通的收藏、聊天和总结，而是同一件事在不同现场留下的内容与变化。

桌面端如果需要一个面向用户的集合名称，当前使用**在意的事**比“知识库”“主题”或“项目”更合适：

- “知识”容易把仍未分清的内容说成结论；
- “主题”容易要求用户先组织和分类；
- “任务”不能容纳只想弄明白的事情；
- “对话”会把产品限制成聊天记录；
- “在意的事”可以同时承接触动、困惑、理解、实践与变化。

“在意的事”是否成为最终页面名称，留到页面信息架构中继续判断；“一件仍在变化的事”作为核心对象先固定下来。

## 六个核心功能

### 1. 留下一点

> 此刻有一点东西，先别丢，也不要逼我现在把它整理成结论。

#### 解决什么

- 阅读时看到一段有触动的内容，但暂时不想离开原文；
- 脑中冒出一句模糊想法，还不知道它属于什么；
- 工作中出现一个发现，但眼前的事情需要继续；
- 想保留当时为什么在意，而不是只留下一个链接或文件名。

#### 用户能做什么

- 选中原文、Agent 回复、代码、原型或工作结果后“留一下”；
- 粘贴链接、文件或一段文字；
- 直接说一句模糊想法；
- 愿意时补一句“这里让我想到……”，不补也可以；
- 保存后撤销，或者直接离开。

#### 它留下什么

- 用户交进来的**一点**；
- 它来自的**原现场**；
- 用户当时愿意留下的表达；
- 恢复现场所需的最少上下文；
- 这一次留下的时间和范围。

#### 不做什么

- 不强制标题、分类和收藏理由；
- 不默认生成长摘要；
- 不把模糊触动自动写成结论；
- 不把“先留一下”自动变成待办或复盘任务。

“留下一点”同时承接阅读中的轻保存和工作中的实践发现，但二者保留各自真实现场，不被统一加工成同一种笔记。

### 2. 从这里接着

> 我回来时，希望认出当时为什么在意、已经分清什么，以及真正停在了哪里。

#### 解决什么

- 收藏以后只剩重新阅读，没有继续入口；
- 对话很长，用户忘了当时真正卡在哪里；
- 回来后只得到一份摘要，仍不知道下一步怎样继续；
- 想继续想，但暂时提不出新的问题；
- 跟着解释时懂了，轮到自己判断时又断了。

#### 用户能做什么

- 从气泡、列表、搜索或一句自然语言找回一件事；
- 先看到真实停点，再按需追溯原文与历史；
- 继续追问、补一句自己的理解或只回看后离开；
- 需要具体对象时选择“换个情形”；
- 先作出自己的判断，再让 Agent 针对实际断点回应；
- 暂停、改变方向或分出旁支。

#### 它形成什么

- 当时为什么在意；
- 已经分清的部分；
- 仍未分清的**未决部分**；
- 一处可以再次进入的**停点**；
- 本次回来带来的新材料、新情形或新问题；
- 讨论方向后来怎样变化。

#### 不做什么

- 不默认展开全部历史；
- 不把一次讨论强行收成结论；
- 不用“继续提问”的空输入框把继续思考的负担重新交给用户；
- 不因为旧主题存在，就不断把用户拉回已经不再关心的问题。

首页点击气泡、飞鸟抵达、气泡从原位置展开，是“从这里接着”的一种视觉表达，不是功能本身的全部。

### 3. 找个对照

> 我不只是想找到相似内容，而是想知道它补充、挑战或限制了我正在想的哪一处。

#### 解决什么

- AI 一直沿着同一种解释继续，用户需要不同视角；
- 用户想找一个反例、真实案例或不同条件下的经验；
- 一篇新文章看起来相关，但不知道它与原问题究竟有什么关系；
- 用户需要找到真正讨论过相关问题的人，而不是把“内容相关”误认为“对方一定能解决”。

#### 用户能做什么

- 说“找个反例”“有没有人遇到过”“换一个情形让我判断”；
- 从自己的既往思考、知乎公开内容和授权资料中寻找对照；
- 查看为什么相关、条件有什么不同、哪些仍无法确认；
- 把材料接为补充、挑战、限制、另一种可能或旁支；
- 表示“这次无关”，拒绝或修复错误关联；
- 在确有需要时查看相关创作者，编辑一份请教草稿，再自己决定是否联系。

#### 它形成什么

- 一份带有具体关系说明的**对照**；
- 原文、真实案例或假设情形的来源区分；
- 对方条件与用户处境的差异；
- 材料补充、挑战或限制的具体位置；
- 仍不能由该材料确认的部分；
- 必要时与相关创作者及其公开经验的连接。

#### 不做什么

- 不把搜索结果列表当成已经完成帮助；
- 不因为关键词相似就自动合并；
- 不把创作者当成默认客服；
- 不将 Agent 的关系判断写成用户已经认可的结论。

“找个对照”是 Trace 与知乎生态连接的主要方式：不是把知乎内容搬进知识库，而是让一件正在形成的事遇到真实的不同。

### 4. 我的理解

> Agent 的解释可以帮助我，但最后要有一处内容真正属于我，并且能由我继续写、改和限定。

#### 解决什么

- Agent 回答有帮助，却没有转化为用户自己的表达；
- 用户只想保留讨论中的一部分，不想收藏整段回答；
- 暂时的猜想、Agent 建议和用户认可的理解混在一起；
- 用户后来修改了想法，但后续仍从旧摘要中带回已经失效的判断。

#### 用户能做什么

- 绕过聊天直接写；
- 从原文或讨论中选取一部分“接到这里”；
- 要求 Agent 帮助组织，但保留自己的表达；
- 标明未决、适用条件或暂时范围；
- 修改、撤销、停用或删除旧判断；
- 保留两种暂时不能合并的解释；
- 查看一处理解怎样形成、后来怎样变化。

#### 它形成什么

- 用户可持续修改的**当前理解**；
- 已分清与仍未分清的内容；
- 理解的依据、来源和适用范围；
- 草稿、尝试与已认可内容之间的区别；
- 当时理解与当前理解的变化；
- 修改后应该怎样影响未来参考。

#### 不做什么

- 不把 Agent 总结自动命名为“我的知识”；
- 不强迫用户选择内容类型；
- 不顺手重写用户已有全文；
- 不把一次猜想自动升级为工作要求或团队规则。

“我的理解”既是一项核心功能，也可能在完整桌面端形成一个长期书写空间。页面怎样呈现，仍由后续界面设计决定。

### 5. 带去用

> 已经想清楚的部分可以进入眼前正在做的事，但用户要看得见它为什么相关、准备怎样使用，并能排除不适合的一条。

#### 解决什么

- 用户不想在每次工作前重新解释已有取舍；
- 过去形成的理解只被保存，没有影响当前做法；
- 尚未成熟的想法想先在真实工作中试一次；
- Trace 提供了上下文，却把“已经送达”误写成“已经应用”；
- 旧理解与本次明确要求发生冲突。

#### 用户能做什么

- 在 Codex 等原生 Agent 中直接开始工作；
- 按需查看“本次带回”的少量相关内容；
- 看见为什么相关、这次准备怎样参与；
- 将一条内容设为这次会参考、这次准备试、只作对照或这次不使用；
- 排除不适用内容，或说明只在当前项目成立；
- 把当前明确要求与过去判断之间的冲突留在本次工作中处理；
- 从一件事把尚未成熟的设想带到当前原型或任务里试一次。

#### 它形成什么

- 一次与具体 Agent、项目和任务相连的**带入**；
- 被带入的理解、问题、尝试或外部对照；
- 为什么与本次工作相关；
- 准备影响哪一处做法；
- 当前项目、任务和时间范围；
- 用户排除、限定或修改的内容；
- 后续判断它是否真正参与工作的依据。

#### 必须分清的四种程度

1. **已带到本次工作**：相关内容已经提供给当前 Agent；
2. **参与了具体做法**：能够指出它影响了哪一处取舍；
3. **落实到了产物**：对应方案、代码、原型或操作已经发生变化；
4. **得到真实使用结果**：后来确实获得了使用或实践反馈。

前一项不能自动证明后一项。“已应用”不作为笼统状态使用。

#### 不做什么

- 不要求用户先进入 Trace 整理，再去原生 Agent 工作；
- 不复制第二套 Agent 聊天；
- 不把全部历史塞进当前任务；
- 不把工作实现完成自动写成想法已经验证；
- 不静默用旧理解覆盖本次明确要求。

“带去用”保留原来的宽度：当前重点是工作阶段，也允许一处理解在之后的阅读、判断或其他真实情境中起作用。具体工作动作可写成“带去当前工作”。

### 6. 结果回来

> 做过之后，让真实发生的结果回到原来的事情里，继续参与比较和修改，而不是再多出一份孤立总结。

#### 解决什么

- 工作完成了，但原来的判断是否成立仍不清楚；
- 实践发现散落在 Agent 对话、原型和任务记录中；
- 一次实现成功被误认为方法已经验证；
- 用户带回结果后，只得到新的总结，没有改变原来的理解；
- 任务结束了，相关问题却被一起当作结束。

#### 用户能做什么

- 直接说“上次那个我试过了”；
- 从当前工作现场选择结果并“带回去”；
- 恢复上次准备尝试的判断、条件和观察点；
- 补充实际发生的事实；
- 写下自己对原因的解释；
- 判断它支持、限制、挑战还是暂时无法判断原理解；
- 修改当前理解、保留冲突，或者再带去尝试一次。

#### 它形成什么

- 与原问题相连的**实践结果**；
- 发生了什么的事实；
- 用户或 Agent 对原因的解释及其不确定性；
- 它与原判断之间的关系；
- 用户愿意留下的**理解变化**；
- 下一次使用时需要继续观察的地方。

#### 不做什么

- 不自动生成完整工作复盘；
- 不把实现完成写成真实使用有效；
- 不把一次成功泛化为长期规则；
- 没有新结果时不编造“本次变化”；
- 不因为任务结束，就宣布相关问题已经想完。

“结果回来”是核心功能名；具体动作使用“带回结果”。首页中的回流轨迹、新节点和理解状态变化，是它的一种视觉表达。

## 必须贯穿六项功能的交互能力

这些能力不单独做成六个功能之外的大模块，也不需要变成一排状态按钮。它们应该在用户实际遇到相关处境时，就地出现并可以忽略。

### 纠正、暂停、分支和改变方向

- 接错了，可以修正当前理解，后续回应跟着变化；
- 暂时不想继续，可以保留真实停点，不强行收成结论；
- 一处旁支可以保留来处，当前主线继续；
- 真正关心的事情变了，可以让新问题成为主线；
- “先收着”和“接下来沿这个想”必须产生不同结果。

### 关联可以被拒绝和修复

- 用户可以说“这次无关”“不是这件事”“接到另一处”；
- 对应不清楚时先核对，不清楚也可以暂时不关联；
- 解除错误关联时保留原始材料和结果；
- 如果错误关联已经影响用户保存的理解，要指出受影响的位置；
- 同一份材料可以与多件事有关，但要分别说明关系，不复制成互不相通的多份内容。

### 用户的修改要影响后续参考

- 明确修改未来理解且对象、范围清楚时，修订并允许撤销；
- 只是本次例外，不自动修改长期理解；
- 删除、停用或限定范围后，后续不再从旧摘要带回失效判断；
- 个人修改不静默扩大为项目或团队规则；
- 已经拿到旧理解的进行中工作，需要知道具体发生了什么变化，但不自动重做。

### 能接回历史，也允许暂时不让历史带路

用户想继续时，及时恢复相关停点；用户想重新阅读或先表达这次感受时，本次回应暂时不使用旧理解。需要比较时，再把当时与现在放在一起。

这不只是隐藏历史界面，而是改变本次帮助所使用的上下文。

## Trace 的内容对象

| 内容对象 | 它是什么 | 它不是什么 |
| --- | --- | --- |
| **一件事** | 用户仍在意、仍可能继续变化的核心对象 | 预先建立的知识主题或必须完成的任务 |
| **一点** | 此刻交进来的片段、触动、问题或工作发现 | 已经整理好的笔记 |
| **原现场** | 原文、作者、工作任务、Agent、项目和必要上下文 | 无限制复制的全部页面、对话或文件树 |
| **停点** | 已经分清什么、仍未分清什么、为什么停在这里 | 自动生成的一段会话摘要 |
| **当前理解** | 用户能够亲自写、改、限定和停用的内容 | Agent 默认替用户形成的结论 |
| **未决部分** | 仍需要判断、比较或等待实际结果的地方 | 催促用户完成的待办 |
| **对照** | 新材料或情形具体补充、挑战、限制了哪一处 | 只有相似度的搜索结果 |
| **来源与人** | 原文、真实经验、创作者及其与当前问题的关系 | 默认客服或权威答案 |
| **带入** | 某项内容为什么进入哪一个 Agent、项目和任务 | 已经参与工作或已经验证的证明 |
| **影响依据** | 一条理解参与具体做法、产物或真实使用的证据 | 笼统的“已应用”标签 |
| **实践结果** | 实际发生的事实，以及它与原判断的关系 | 自动泛化的成功经验 |
| **理解变化** | 用户愿意保留的补充、限制、挑战或修订 | 另一份互不相通的新总结 |

这些对象构成 Trace 的专属内容。轨迹、支流、气泡、飞鸟和回流动效用来表现它们之间的连续关系，但视觉形式不能代替对象本身。

## 一条完整的产品链路

```text
此刻遇到一点东西
    ↓ 留下一点
保留原现场，不要求立即整理
    ↓ 从这里接着
形成停点，逐渐分清问题
    ↓ 找个对照
遇到不同材料、情形或真实经验
    ↓ 我的理解
用户写下、修改或保留未决
    ↓ 带去用
相关部分进入当前工作或真实情境
    ↓ 结果回来
事实、解释与新判断接回原来的事情
    ↓
当前理解发生变化，在以后继续起作用
```

用户不需要每次走完整条链路：

- 只留下后离开，也成立；
- 分清一个区别但不整理，也成立；
- 没有历史时直接工作，也成立；
- 工作中没有新发现，不强行生成结果；
- 只是回来查看，不继续，也成立。

完整链路用于检查产品有没有断点，不是要求用户遵守的流程。

## 与详细功能候选的对应

| 详细候选 | 当前归入的核心功能 |
| --- | --- |
| 1. 带入材料，随手留下一点 | **留下一点** |
| 2. 围绕具体一处展开讨论 | **从这里接着** |
| 3. 找到有用的对照与请教线索 | **找个对照** |
| 4. 换个情形，自己试着判断 | **从这里接着**为主，按需调用**找个对照** |
| 5. 自己写，也可以请 Agent 帮着整理 | **我的理解** |
| 6. 找回上次停在哪里 | **从这里接着** |
| 7. 把新发现接到之前的一处思考 | **找个对照**与**从这里接着** |
| 8. 让相关理解参与当前工作 | **带去用** |
| 9. 带着一个尚未成熟的想法试一次 | **带去用** |
| 10. 留下工作现场的新发现 | **留下一点**，保留工作原现场 |
| 11. 带着结果回来继续比较和修正 | **结果回来**，必要时更新**我的理解** |

原有 1—11 项候选继续负责描述不同处境下的完整行为；六项核心功能负责让用户和产品拥有稳定、可识别的功能语言。

## 功能与产品空间的关系

六个功能是用户能够完成的动作，不应该直接变成六个固定导航项。完整桌面端后续可能需要这些产品空间：

| 产品空间（待界面层继续判断） | 主要承接什么 |
| --- | --- |
| **在意的事** | 找到仍在变化的事情，从真实停点重新进入 |
| **我的理解** | 长期书写、修改、限定和比较自己的理解 |
| **工作现场** | 查看当前工作、本次带入、实际影响和带回结果 |
| **来源与人** | 查看原文、外部对照、真实经验与创作者 |
| **全部痕迹** | 搜索、追溯、比较时间变化和修复错误关联 |

这组产品空间暂不作为正式侧栏或页面数量。一个功能可以跨越多个界面层级：

- “留下一点”可以发生在知乎原文、桌面悬浮入口和原生 Agent；
- “从这里接着”可以从首页气泡、小浮窗、大浮窗或检索结果进入；
- “带去用”主要发生在原生 Agent 旁边，不要求先进入桌面端；
- “结果回来”可以从工作现场直接完成，也可以在桌面端深入比较。

具体功能出现在哪里、界面怎样逐层展开，继续由[产品界面与交互设计](../产品界面与交互设计/README.md)承接。

## 当前采用的功能判断

> Trace 的核心不是把材料组织成知识库，而是让一件仍在变化的事能够跨越阅读、讨论和实践继续形成。

当前正式采用六个核心功能名：**留下一点、从这里接着、找个对照、我的理解、带去用、结果回来**。

它们共同形成 Trace 自己的内容：**一点、原现场、停点、当前理解、未决部分、对照、带入、影响依据、实践结果和理解变化**。

后续可以继续推敲按钮文案、页面名字与视觉表现；如果真实使用揭示新的处境，也可以回到交互链路补充。但不因为别的产品拥有某个模块，或某种 UI 形式看起来完整，就把它直接增加为 Trace 的核心功能。

# 整体交互形态

> 我在桌面有一个悬浮入口，点击就能直接输入；需要更多帮助时，再展开为小浮窗、大浮窗和完整桌面端。

这是 Trace 当前的整体界面与交互架构候选，依据[功能与交互骨架](../产品功能与交互方案/功能与交互骨架.md)、[功能候选与使用方式](../产品功能与交互方案/功能候选与使用方式.md)和已经收束的[核心功能与内容对象](../产品功能与交互方案/核心功能与内容对象.md)继续展开。这里确定的是不同界面形态怎样承接同一件事，不代表页面布局、视觉形式和具体技术已经确定或验证。

## 现有 Demo 为什么不适合作为主界面骨架

本轮提供的旧 Demo 截图采用固定三栏：左侧讨论历史、中间对话、右侧思考状态。问题不只在于它看起来寻常，而在于它把产品逻辑定成了“新建讨论，持续和 Agent 聊天”。

- 用户一进入就面对本轮目标、当前理解、待回答问题和候选判断，默认他已经准备进行一场正式的深度讨论。
- 聊天成为中心，自己写、随手留下、正常工作、只回顾和暂时停止都退到了次要位置。
- “清晰度 68%”一类表达把仍在形成的理解包装成可精确测量的状态，缺少真实依据。
- 内部需要区分的原始现场、当前理解和未决问题被同时铺开，反而要求用户管理产品结构。
- 从一点触动到深入整理之间没有轻重变化；无论用户此刻需要多少帮助，都被带入同一个重界面。

因此，可以保留其中对原文、讨论、理解和未决问题的内容需求，但不继续把三栏聊天工作台作为 Trace 的主界面骨架。

## 核心交互命题

> Trace 不是一个必须先进入的 App。它先在用户所在的桌面与工作现场接住一点东西，随着事情变复杂，才逐渐长成完整的工作空间。

同一件事从轻到重展开：

**桌面悬浮入口 → 极简输入框 → 小浮窗与气泡 → 大浮窗 → 完整桌面端**

这不是五套独立内容，也不是五个必须经过的步骤。用户刚才带来的材料、说过的话、当前停点和自己的表达，在展开时保持是同一件事；收起以后，也不只剩下一条聊天历史。

## 五级展开

### 0. 桌面悬浮入口

平时安静地存在于桌面边缘，需要时一眼能找到，不靠不断跳动、红点和待办数量制造存在感。

用户可以：

- 点击打开极简输入框；
- 用快捷方式唤起；
- 后续根据实际宿主能力，再考虑接住选中文字、文件或链接；
- 再次点击或取消，立即收起。

它首先解决的是：**我现在只有一点东西，不值得为了它打开完整应用。**

### 1. 极简输入框

点击悬浮入口后，先出现能够直接输入的一处，而不是完整聊天页。

用户可以说：

> 这里有点意思，先留一下。
>
> 为什么收藏以后总想不起当时为什么在意？
>
> 这个先别改成长久规则。
>
> 之前那个我刚刚试过了。

如果存在刚刚选中的原文、工作片段或文件，可以安静地显示一个来源标记，让用户知道现场已经跟过来，但不占据整个界面。

提交后，根据当前意图完成最小回应：

- 只是留下，就确认已经接住并允许离开；
- 是一个问题，就从具体位置开始回应；
- 带回了结果，就尝试接回对应的事情；
- 对应关系不明确，才轻轻核对；
- 用户继续往下说，再逐渐展开为小浮窗。

这里不要求用户先选择收藏、讨论、工作或复盘模式。

### 2. 小浮窗与气泡

小浮窗承接几轮短讨论、纠正、暂停、旁支、轻提示和快速接续，也允许用户补一句自己的理解。它不承担完整 manual、所有历史版本、全局检索和复杂关系管理。

气泡不是每一条用户消息与 Agent 回复，也不是催促用户处理的通知。暂时把它理解为：

> **一轮有意义的片段，或者一个仍然可以继续的停点。**

一个气泡可以来自：

- 用户留下的一段触动；
- 围绕它发生的一小轮讨论；
- 工作中出现的一条实践发现；
- 一次后来带回的新结果；
- 一个暂时放下、但仍保留来处的旁支。

收起时，气泡显示用户能认出来的原话与真实停点，而不是一段自动摘要。例如：

> **附言是否真的必要？**
>
> 上次停在：还没分清是缺少个人表达，还是原文现场不足。

点击气泡，可以在原位置展开相关内容；用户可以继续、先放着、指出这次无关，或者把它展开为大浮窗。

### 3. 大浮窗

用户真正开始深入讨论、比较材料、整理理解或带着实践结果回来时，小浮窗围绕刚才同一件事继续展开。

大浮窗需要容纳：

- 当前正在弄清的问题；
- 相关原文与实践现场；
- 当前讨论；
- 用户自己写的理解；
- 尚未解决的部分；
- 准备尝试的做法；
- 后来带回的实际结果；
- 当时与现在发生的变化。

这些内容不应默认同时占据同等视觉权重。正在读原文时，以原文为中心；正在讨论时，以当前冲突为中心；正在自己整理时，以用户的文字为中心；带回结果时，以“上次停在／这次发生”为中心。其他部分按需展开。

大浮窗解决当前这一件事的深入，不负责管理用户全部历史。

### 4. 完整桌面端

桌面端不是最大号聊天窗口。它承担小浮窗不适合承担的长期工作：

- 找回过去在意的事情；
- 查看少量仍在变化的事情；
- 搜索材料、理解与实践结果；
- 自己长期书写和修改；
- 比较当时的理解与现在的理解；
- 修复错误关联；
- 查看某条理解在哪些工作中被参考；
- 管理个人与项目范围；
- 在多件事情之间建立真实关系。

桌面端可以包含已提出的全部功能，但首页不应该同时展示全部功能。搜索、全部内容、自己的整理、来源和设置可以保持可达，不需要在首页固定铺成一列功能菜单。

## 桌面首页：不是导航页，而是安静的接续面

问山的首页以明确学习目标和路线规划为中心，这与它的产品定义一致。Trace 可以借鉴留白、中心聚焦和完整产品感，但不能照搬“学习目标输入＋路线卡片＋功能导航”，因为用户也可能只有模糊触动、正在工作、想从旧问题继续，或者想重新阅读而暂时不受旧理解影响。

Trace 首页第一眼先完成两件事：

1. 我现在可以把一点东西交进来；
2. 我能够认出，有哪些事情仍然可以从某处继续。

### 中心：此刻正在接续的一件事

如果最近有明确的事情，首页中央可以先显示：

> **上次停在这里**
>
> 你还没分清，收藏后接不回来，是缺少个人表达，还是原文现场不足。

下面提供一处轻输入：

> 写下现在想到的，或带来新的材料……

同时保留“先不带回以前的理解，重新开始看”的入口，不因为存在历史就提前替用户解释这次的新感受。

### 周围：少量仍然活着的气泡

最近还没想清楚、有了新材料、正在尝试或带回新结果的事情，可以围绕中心安静出现。它们不是按时间排列的聊天列表，也不需要整齐铺满成知识卡片。标题优先使用用户自己的表达。

点击一个气泡，它从原位置展开为大浮窗，而不是跳进标准详情页。

### 边缘：完整功能保持可达

搜索、全部内容、自己的整理、来源、项目范围和设置位于更低层级，需要时再出现。首页不为了证明功能齐全，把所有入口同时摆出来。

## 形成 Trace 自己的交互辨识度

正式产品感不主要来自更多装饰、渐变、吉祥物、玻璃拟态或复杂知识图谱，而来自一套持续一致的交互语法：

- 内容随着用户意图逐渐长大；
- 收起不会消失，而是留下真实停点；
- 新材料进入时，能够表现补充、挑战、另一种可能或暂时无关；
- 用户的修订反映在同一件事上，不不断生成互不相通的新卡片；
- 气泡展开、旁支分出、实践结果回来，都在视觉和操作上保持连续。

> 这还是我之前在意的那件事，它只是继续长了。

这种连续变化本身可以成为 Trace 的品牌感，而不是给普通聊天界面再套一层视觉皮肤。

## 不同层级主要承接什么

| 界面层级 | 主要承接 |
| --- | --- |
| 桌面悬浮入口 | 随时进入，不要求离开当前现场 |
| 极简输入框 | 留下材料、模糊想法、工作发现和直接带回结果 |
| 小浮窗与气泡 | 短讨论、纠正、暂停、旁支、轻提示和快速接续 |
| 大浮窗 | 深入讨论、材料对照、自己整理、实践比较和修改理解 |
| 完整桌面端 | 主动找回、长期书写、跨时间比较、关系修复和多件事情组织 |
| 桌面首页 | 此刻进入与从真实停点继续，不承担全部具体操作 |

同一项功能可以跨越多个层级。例如“把新发现接到以前的思考”，可以在阅读现场先显示轻提示，在小浮窗里核对关联，在大浮窗里比较新旧内容，在桌面端修改当前理解。不是一个功能必须对应一个页面。

## 需要守住的边界

- **气泡不是通知和待办**：留下很多东西，不等于桌面边缘应堆满红点。
- **展开不能丢失对象身份**：进入大浮窗或桌面端后，不重新变成一份孤立聊天记录。
- **产品不擅自占据屏幕**：可以建议展开，但不因为回复变长就自动撑成全屏。
- **首页极简不等于功能消失**：完整功能放在合适层级，不为了极简而让用户找不到。
- **视觉形式仍待讨论**：轨迹、气泡、动效和页面构图是候选，需要结合后续 UI idea 与原型判断。

## 当前形成的整体判断

> Trace 以悬浮入口伴随用户；以气泡保留仍可继续的一小轮；以大浮窗处理当前这一件事；以完整桌面端管理长期形成和变化。

这套形态是后续零碎 UI idea 的上层容器。暂时接不上的形式可以先保留；如果它揭示新的真实需要，再回头修订这套架构，不为了维持完整而硬归类。

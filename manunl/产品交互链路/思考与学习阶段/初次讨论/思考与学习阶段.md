# 思考和学习的阶段

> 可以深度与Agent讨论、思考、沉淀、和定义能力，允许中间打断、保留、追溯

## 核心

- **把需要的材料带进来，并能返回原文。**
- **在用户授权范围内读取相关收藏、创作或既有思考，而不是全量导入。**

带着处境进入 → 接准他在意什么 → 用解释或对照推进一处 → 留下本人认可的进展或未决点

这是一条帮助主线，不是每次都要跑完的固定流程；可以只收下，也可以在任意一处先停。

## 初次讨论时

### 带着现场交进来

> 以尽量低的负担，接准用户为什么把它交过来
>
> 有当前对话就利用当前对话；有选中片段和一句附言就从那里开始；实在不清楚才轻问一句。只是收藏时，也允许不继续。

- 发现的一些原文
- 感知的一些现象
- 无意间的一些奇思妙想和模糊的想法
- 也许是和谁的讨论或者观看什么东西中产生的想法

#### 用户的感受

> - 我不用很麻烦重新搬运背景，产品知道我是从哪里开始说这件事的
> - 当我感知到一些东西时，产品能帮我一点点摸清，隐式地引导我如何提问（产品不会直接说如何提问，但是它回答的内容会让我激发出关联，产生认知位移，产生提问的渴望）
> - 好的帮助，不一定让用户问得更多，也可能让他终于不需要继续问了

### 帮我把问题弄清

- 每次只推进最关键的一处
- 当我感知到一些东西时，产品能帮我一点点摸清，隐式地引导我如何提问（产品不会直接说如何提问，但是它回答的内容会让我激发出关联，产生认知位移，产生提问的渴望）
- 尽量减少认知疲劳，思考和对话较多时，能帮用户先收住进展，后续休息后再进行；不只凭对话长度判断用户是否疲劳。

#### 一次回应至少应当帮助用户发生某种变化

- 原来说不清哪里不对，现在能指出具体冲突；
- 原来把两个问题混在一起，现在能分开判断；
- 原来只有一个猜想，现在知道缺什么证据；
- 原来不知道怎么继续，现在有一个可以尝试的动作。

先结合现场提出一个有依据、可被用户纠正的理解，不只抛问题，也不急着替用户定论。

#### 讨论中可以打断、保留、再继续

- 接错了，就先纠正理解，不让用户重新搬运全部背景。
- 冒出旁支，可以先留下，不必改变当前主线。
- 暂时不同意或想停下来，就保留已经分清的地方和还卡住的问题，不强行收成结论。

### 带来相关历史与外部对照

按当前缺口调用，不是每次讨论的必经阶段；理解接错时，先纠正，再决定要不要查历史或找材料。

- 对照材料可以来自内部认知源，也可以来自B站、小红书、知乎、X、Reddit等（目前以知乎为主）
- 用户以前相关的理解或未决问题；
- 支持当前看法的经验；
- 反例、不同处境或另一种解释；
- 值得回看原文、进一步了解的创作者，
- 能基于答主/博主的回答，整理向他们请教的简单提问草稿；是否联系由用户决定。
- 对当前问题有作用才加入，也不必为了反茧房，每次都刻意唱反调。

### 把讨论留下的进展，变成下次能使用的东西

| 用户正在做的事（举例） | 值得留下的结果（举例）                |
| ----------- | -------------------------- |
| 想弄明白一个问题    | 当前理解、依据，以及仍未解决的部分          |
| 想形成工作流      | 适用情境、关键步骤、检查方法与例外          |
| 想建立领域模型     | 关键概念之间的关系、为什么有关，以及尚不理解的连接  |
| 只是被触动       | 原片段、在意之处或一个未成形的问题，不强行加工成结论 |

- 不要让所有思考最后都变成同一种摘要卡片
- 提出的解释和用户认可的理解要有区别。用户可以修改、暂存、拒绝，不必被迫把每次讨论都正式“采用”，用户拥有高度决策权，能修改manual区域的内容，让用户有地方可以验证自己的认知进化

#### manual修改后，后续也要跟着变

- 用户修改、删除或限定理解的范围后，后续接续以最新状态为准；未确认的解释不当作用户已认可的结论。
- manual留下的是理解与变化，是否真正有用，还要看后续能否解释、使用和修正，不是写下来就证明了认知进化。

## 在下一次相关事情里帮上忙，并允许修正

用户重新工作或讨论时，Trace 带回的不只是“你以前看过这篇文章”，而应是：

> “你上次在这个问题上形成了这样的理解。这次的情况有这些相同点和差异，可能影响眼前这一步。”

如果是未决问题，就应让用户从断点继续。

用过之后，新事实也能回来：原理解成立、需要缩小范围，还是应该撤回。

### 通向工作阶段的出口

- **把用户确认的理解带到原生工作 Agent，并接回后续使用的结果。**

如果带入的是一个工作流，就应能帮助当前 Agent 使用它。

这是用户想把理解带去具体工作时的一种出口，不是思考与学习阶段的必经步骤。能够重新看待一个现象、分清原来混淆的东西，或者问出以前问不出的问题，即使没有形成工作流，也可以是这一阶段的收获。

## 小tips

满足三个条件：**有具体触发、有明确帮助、可以忽略。** 普通时候不出现。

| 触发时刻          | 可以出现的小提示              | 它保护什么         |
| ------------- | --------------------- | ------------- |
| 两篇材料表面矛盾      | “它们可能针对不同处境，要先看差异吗？”  | 不急着替用户裁决对错    |
| 讨论冒出有趣旁支      | “这个想法可以先留下，不改变当前主线。”  | 灵感不丢，注意力也不被抢走 |
| 模型补出了原文没有的解释  | 就地标明“这是推断”，附原文入口      | 来源与推断不混淆      |
| 用户准备把一次经验长期使用 | “目前只在这个项目里试过，先限定在这里？” | 不把局部经验泛化      |
| 用户回来继续        | “上次停在这里；这次新增的是这段材料。”  | 不需要重新阅读全部历史   |
| 一条理解可能影响团队    | 明确显示“仅个人／当前项目／提交团队讨论” | 个人判断不静默变成团队规则 |

一个取舍：**能用清楚的状态和标注解决，就不要弹出一句话要求用户回应。**  
例如“这是推断”“尚未验证”，更适合安静地显示，而不是每次都打断对话

## 团队和个人先分开验证

先验证个人的理解能否在下一次帮上忙。团队再明确谁确认、在哪里生效；个人修改不自动变成团队规则或改写已发布能力。

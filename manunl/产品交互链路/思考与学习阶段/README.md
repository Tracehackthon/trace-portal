# 思考与学习阶段

> 先分清用户处在哪个时期，再看他当下是什么理解状态。讨论接得顺，不等于已经把学习中的帮助想清楚。

## 按时期看主线

- [初次讨论时](初次讨论/思考与学习阶段.md)：用户把一件在意的事情交进来，产品怎样帮助他逐渐弄清楚。
- [讨论之后与再次接续时](讨论之后与再次接续/思考与学习阶段.md)：离开之后，怎样自己整理、回顾，或者带着新的发现继续。
- [初次讨论后的原始提问](初次讨论/思考与学习阶段_续（提问）.md)：保留原来的问题，不用整理后的正文覆盖。

## 跨时期的理解处境

这些不是第三个时期，也不是新增的功能模块。它们可以发生在上面两个时期里，用来检查：已有链路在具体处境下，是否真的知道怎样帮助用户。

- [还在意，但暂时想不出怎么继续](跨时期的理解处境/还在意，但暂时想不出怎么继续.md)
- [跟着解释懂了，自己判断时又断了](跨时期的理解处境/跟着解释懂了，自己判断时又断了.md)
- [聊着聊着，真正关心的事情变了](跨时期的理解处境/聊着聊着，真正关心的事情变了.md)
- [想重新看，却被旧理解带了回去](跨时期的理解处境/想重新看，却被旧理解带了回去.md)

第一种来自本次讨论中用户描述的“空洞期”；其余三种是用于检验链路的情境假设，尚未经过用户访谈或实际使用验证。对应的帮助方式也仍需验证，不因为写进文档就当成已经解决。

## 与工作阶段的边界

工作中的帮助，常常围绕把眼前这件事做成；思考与学习中的帮助，不一定已经有明确要做成的事，用户可能还在发现自己关心什么。

这里不要求每次都有结论、产物或工作流。重新看待一个现象、分清一个区别、问出一个以前问不出的问题，都可能是收获。

把理解带到工作 Agent 是一种出口，不是本阶段成立的必要条件。这不是把工作与学习彻底分开，而是不拿工作交付作为所有思考与学习的完成标准。

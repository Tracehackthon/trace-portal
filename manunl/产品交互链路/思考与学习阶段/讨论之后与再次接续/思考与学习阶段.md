# 思考和学习的阶段

> 初次讨论之后，用户可以离开，可以自己整理，也可能已经忘记；等到想回顾，或者又发现了什么、感受到了什么时，之前的思考还能继续接上。

接续[初次讨论时](../初次讨论/思考与学习阶段.md)，整理自[续篇提问](../初次讨论/思考与学习阶段_续（提问）.md)。

## 核心

- **不是让用户一直讨论，而是让讨论留下的进展在离开之后仍然有用。**
- **不必每次从零开始，也不被之前的理解固定住。**
- **用户可以自己写、自己整理，需要帮助时再让 Agent 参与。**

离开一轮讨论 → 因为回顾、新发现或眼前的需要再次进入 → 恢复相关理解 → 继续、使用或修正

这不是必须依次走完的流程。第一次讨论可以已经想清楚，也可以只是推进了一点，留下还没弄明白的地方。

## 讨论之后与再次接续时

下面是这一时期可能发生的几种处境，不是依次经过的步骤。自己整理也可以发生在讨论中，不必等讨论结束。

### 用户已经忘记了之前的讨论

> 产品不是要求用户记住每一次讨论，而是在后来又需要时，让之前想过的东西有机会帮上忙。

- 用户可能已经不记得自己讨论过，不能只等他主动搜索历史。
- 在用户授权接入的相关场景里，结合眼前的事情带回有用的理解，说明它为什么与这次有关，而不只是提醒“你以前看过这个”。
- 带回的是当时为什么这样想、已经分清的地方，以及这次可能不同的条件。用户后来修改过，就以新的理解为准。
- 没有相关需要时，不因为很久没打开就不断提醒复习；用户也可以忽略或说“这次不是这个问题”。

#### 用户的感受

> - 即使我已经忘记，之前想明白的东西也没有白费，眼前需要时还能帮上忙。
> - 产品不会拿旧结论替我决定现在应该怎么想。

### 用户想要回顾之前的讨论

> 不只是找到一条聊天记录，而是重新知道自己当时为什么在意、想到了哪里。

- 用户可能想找当时的一句话，也可能想看自己是怎么一步步想清楚的。
- 先帮助恢复当时的问题、形成的理解和仍未解决的地方；需要细看时，再回到原始讨论和材料。
- 如果后来改过想法，能分清当时的理解和现在的理解，不把不同时间的说法混在一起。
- 回顾之后可以继续讨论，也可以只是看明白后离开，不必被要求再做一项任务。

#### 用户的感受

> - 我不用重新读完全部对话，才能知道自己走到哪里了。
> - 我想追溯时，也能找到当时为什么会这样想，而不只剩下一段摘要。

### 用户想要自己手写沉淀

> 这是产品要关注的：让用户有地方自己整理自己的收获，不只接收 Agent 整理好的东西。

- 可以不先和 Agent 聊天，直接写下自己的理解，也允许只写一半、暂时说不清。
- 这里的“手写”首先是自己组织和表达，不限定输入形式，也不是要求每个字都亲手输入。
- 用户需要时，Agent 再帮助检查、对照或补充；保留用户自己的表达，不默认把它重写成另一套话。
- 用户自己写的、Agent 建议的，以及用户认可的理解要能分清，不能因为出现在 manual 里就一律当成已确认结论。
- 用户修改、删除或限定理解后，后续接续也要跟着变，不只是编辑区里的文字变了。
- 不把“每次讨论后写一份心得”变成必经步骤。写下来也不等于已经理解，还要看以后能否解释、使用和修正。

#### 用户的感受

> - 我有地方用自己的话整理收获，而不是只能接受一份看起来很完整的总结。
> - Agent 可以帮我，但这些东西仍然是我能决定、能修改的。

### 又发现了什么，带着现场交进来

> 用户又看到了原文、感知到了现象，或者冒出了一个想法。入口看起来和第一次一样，但不应该把他当成第一次来。

- 先接准这次为什么把它交过来，不急着把所有旧背景带进来。
- 如果有关，帮助分清：它补充了之前哪一处，挑战了什么，还是让原来卡住的问题有了新的线索。
- 如果只是表面相似，或者用户想讨论的是另一件事，就允许另起一条，不强行合并。
- 新材料不自动推翻旧理解，旧理解也不盖过新发现。先看它们各自在什么条件下成立，再由用户判断是否修正。
- 这次有了新的进展，就留下变化和仍未解决的部分；没有形成结论，也能从这次停下的地方再继续。

#### 用户的感受

> - 我不用重新搬运全部背景，也不需要证明自己现在的想法与以前一致。
> - 我知道这次的新发现，究竟让之前哪一处往前走了一点；如果是新的事情，也有地方开始。

## 贯穿前后讨论的外部对照

### 想知道外部案例，以及和自己想法异曲同工的东西

> 有没有人这样想过、这样做过？他们已经走到了哪里，我能借鉴什么？

这延续初次讨论中的“带来相关历史与外部对照”，不是讨论结束后的必经阶段。用户在自己整理、回顾或带来新发现时，都可能需要它。

- 先看用户现在想借助案例弄清什么，不只推荐相似文章。
- 说明相似的是表面形式，还是底下的问题、思路和解决方式。
- 保留不同处境、适用条件和不能直接照搬的地方；找到相似案例，不等于证明自己的想法一定成立。
- 能回到案例原文和创作者；哪些来自原文、哪些是 Agent 的推断，要分清。
- 对照后回到用户自己的事情：它补充了什么、挑战了什么，或者仍然没有回答什么。不必为了扩展而不停扩展。

#### 用户的感受

> - 我不只是看到了“别人也做过”，而是知道他们的经验对我有什么用。
> - 我可以借鉴，也可以保留自己的不同，不被外部案例带跑。

## 这一时期要真正接住的东西

> 我可以离开，也可以忘记；可以自己写，也可以带着新发现回来。之前的思考仍然有机会参与下一次，而不是每次都从零开始。

不是每次都要产出新的结论或更多笔记。能恢复一段理解、用自己的话整理清楚、修正一处判断，或者重新知道卡在哪里，都可以是这一轮的收获。

是否真正帮上忙，要看用户后来能否接着想、解释或使用，而不只看保存了多少内容、回顾了多少次。
